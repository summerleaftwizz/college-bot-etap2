# College Schedule Bot

Telegram-бот на **aiogram 3** для показа расписания колледжа. Данные берутся из
публичной папки Яндекс.Диска: бот следит за появлением новых файлов
`studentam\\\\\\\_\\\\\\\*.xlsx`, парсит их и рассылает расписание подписчикам.

Работает через **polling** (без webhook). Данные хранятся только в БД —
файловая система PaaS-платформы эфемерна.

\---

## Возможности

* Фоновый `asyncio.Task` («watcher») опрашивает Яндекс.Диск каждые
`POLL\\\\\\\_INTERVAL\\\\\\\_MINUTES` (по умолчанию 3).
* При появлении нового файла `studentam\\\\\\\_ГГГГ-ММ-ДД.xlsx`:

  * скачивает и парсит **все группы**;
  * сохраняет расписание в БД;
  * рассылает всем подписанным пользователям их группу.
* Защита от дублей: файл попадает в `known\\\\\\\_schedules` только после успешного
парсинга и рассылки; при рестарте уже обработанные файлы не рассылаются.
* Главное меню — закреплённая Reply-клавиатура: «📅 Сегодня», «📅 Завтра»,
  «🔔 Что сейчас», «👥 Сменить группу».
* Команды: `/start`, `/today`, `/tomorrow`, `/change_group`,
`/subscribe`, `/unsubscribe`, `/admin_known`, `/admin_reparse`.
* «Что сейчас»: какая пара идёт, сколько осталось, когда начнётся следующая.
* Graceful shutdown по `SIGTERM`/`SIGINT` (отмена watcher'а, закрытие сессий).

## Локальный запуск

Требуется **Python 3.11+**.

```bash
cd college-schedule-bot
python -m venv .venv
# Windows:
.venv\\\\\\\\Scripts\\\\\\\\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
copy .env.example .env      # или cp .env.example .env
# заполни .env (см. ниже)

python app.py
```

Без PostgreSQL можно локально использовать SQLite — в `.env` укажи:

```
DATABASE\\\\\\\_URL=sqlite+aiosqlite:///./bot.db
```

Прогнать тесты парсера:

```bash
pytest -q
```

## Переменные окружения (.env)

|Переменная|Обязательна|Описание|
|-|-|-|
|`BOT\\\\\\\_TOKEN`|да|Токен бота от `@BotFather`|
|`DATABASE\\\\\\\_URL`|да|`postgresql+asyncpg://...` (или sqlite для локального запуска)|
|`ADMIN\\\\\\\_ID`|нет|Telegram ID админа для `/admin\\\\\\\_known`, `/admin\\\\\\\_reparse`|
|`POLL\\\\\\\_INTERVAL\\\\\\\_MINUTES`|нет|Интервал поллинга, мин (по умолчанию `3`)|
|`YADISK\\\\\\\_PUBLIC\\\\\\\_URL`|да|Публичная ссылка на папку Яндекс.Диска|
|`TZ\\\\\\\_NAME`|нет|Часовой пояс (по умолчанию `Asia/Novosibirsk`)|
|`REQUEST\\\\\\\_TIMEOUT`|нет|Таймаут HTTP-запросов, сек (по умолчанию `15`)|
|`REQUEST\\\\\\\_RETRIES`|нет|Число ретраев (по умолчанию `3`)|
|`BROADCAST\\\\\\\_DELAY\\\\\\\_MS`|нет|Задержка между сообщениями при рассылке, мс (по умолчанию `50`)|
|`SHOW\\\\\\\_TIME`|нет|Показывать время пары в тексте (`true`/`false`)|

Как получить `BOT\\\\\\\_TOKEN`: `@BotFather` → `/newbot` → скопировать токен.
Как узнать `ADMIN\\\\\\\_ID`: отправь сообщение боту `@userinfobot`.

> Драйвер БД подставляется автоматически: если `DATABASE\\\\\\\_URL` начинается с
> `postgresql://` или `postgres://`, бот сам превращает его в
> `postgresql+asyncpg://` (см. `db/\\\\\\\_\\\\\\\_init\\\\\\\_\\\\\\\_.py`).

## Деплой

### Amvera

1. Залей проект в Git-репозиторий.
2. В Amvera создай приложение и добавь PostgreSQL (выдаст `DATABASE\\\\\\\_URL`).
3. Пропиши переменные окружения (`BOT\\\\\\\_TOKEN`, `YADISK\\\\\\\_PUBLIC\\\\\\\_URL`, `ADMIN\\\\\\\_ID`, …).
4. В `amvera.yml` укажи команду запуска:

```yaml
   run:
     command: python app.py
   ```

5. Деплой. Логи — во вкладке логов приложения (бот пишет в stderr).

Файл `.amveraignore` исключает из загрузки `venv/`, `.env`, `\\\\\\\_\\\\\\\_pycache\\\\\\\_\\\\\\\_/`,
`\\\\\\\*.db` и прочий мусор.

### Railway

1. Залей проект в Git-репозиторий, импортируй в Railway.
2. Добавь PostgreSQL (платформа выдаст `DATABASE\\\\\\\_URL`).
3. Пропиши переменные окружения.
4. Деплой идёт по `Procfile` (`worker: python app.py`) — порт не нужен.

## Формат данных и Excel

**Структура публичной папки** (фактическая) — файлы лежат в корне:

```
/studentam\\\\\\\_2026-10-23.xlsx
/studentam\\\\\\\_2026-10-24.xlsx
/studentam\\\\\\\_2026-10-26.xlsx
/prepodovatelyam\\\\\\\_2026-10-23.xlsx   (преподаватели — игнорируются)
```

Бот обрабатывает только `studentam\\\\\\\_\\\\\\\*.xlsx`; дата берётся из имени файла
(`studentam\\\\\\\_2026-10-26.xlsx` → `26.10`).

**Формат внутри .xlsx** (проверено на реальных файлах):

* один лист (назван по дню недели);
* колонка `0` = номер пары;
* группы идут **горизонтальными блоками** (по несколько групп в ряд), а сами
блоки — **друг под другом**;
* у каждой группы две колонки: предмет (заголовок «Дисциплина»/«Предмет»)
и кабинет (заголовок «Ауд.»/«Кабинет»);
* строки с ФИО преподавателя чередуются со строками пар (в колонке номера пары
пусто) — они пропускаются.

Пример (упрощённо):

|Пара|Дисциплина (1ОГР-26-9)|Ауд.|Дисциплина (БУХ-26-9)|Ауд.|
|-|-|-|-|-|
|1|История|304|Химия|205|
|2|Математика|307|—|—|

Парсер сам находит колонки по синонимам и названия групп по regex:

* синонимы колонок — `config.ParserConfig` (`SUBJECT\\\\\\\_SYNONYMS`,
`ROOM\\\\\\\_SYNONYMS`, `LESSON\\\\\\\_NUM\\\\\\\_SYNONYMS`);
* названия групп — `GROUP\\\\\\\_NAME\\\\\\\_PATTERN` (по умолчанию
`^\\\\\\\[А-Яа-яЁёA-Za-z0-9]+-\\\\\\\\d{2,4}(-\\\\\\\\d+)?$`, подходит для `1ОГР-26-9`,
`БУХ-26-9`, `ОПИр-25-9`, `ОГР-23`).

Если формат файла другой — поправь `ParserConfig` в `config.py`.

Если распарсить файл не удалось — ошибка пишется в лог, файл **не** помечается
обработанным, и бот повторит попытку в следующем цикле.

## Как работает watcher

```
каждые POLL\\\\\\\_INTERVAL\\\\\\\_MINUTES:
  список файлов в корне публичной папки
  для каждого studentam\\\\\\\_\\\\\\\*.xlsx, которого ещё нет в known\\\\\\\_schedules:
      скачать (по прямому file-URL из ответа API)
      парсить все группы -> сохранить в БД
      рассылка подписанным (задержка 50 мс) -> пометить файл обработанным
```

* Файл попадает в `known\\\\\\\_schedules` **только после** успешного парсинга и
рассылки. Если рассылка упала — записи откатываются и попытка повторится.
* Каждая отправка обёрнута в `try/except`: если пользователь заблокировал бота,
он помечается `inactive=true`, бот не падает.

\---

## Полезное

* Telegram-лимит рассылки \~30 msg/sec; задержка задаётся `BROADCAST\\\\\\\_DELAY\\\\\\\_MS`.
* Всё логирование идёт в **stderr** — платформа собирает его автоматически.
* Публичный API Яндекс.Диска не требует токена: используется `public\\\\\\\_key`
(публичная ссылка). Скачивание идёт по готовому `file`-URL из ответа API —
это надёжнее эндпоинта `/download`.
